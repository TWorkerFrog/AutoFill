# AutoFill — техническая документация

Документ описывает архитектуру текущей версии (`1.1.0`), правила безопасности и
сборку. Пользовательская инструкция находится в `README.md`.

---

## 1. Назначение

AutoFill заполняет шаблоны грамот/дипломов (JPG/PNG) списком ФИО. Для каждого
человека создаётся PNG, отдельный PDF или страница общего PDF. Пользователь
управляет шрифтом, цветом, интервалами, разбиением ФИО и положением блока.

Ключевые требования:

- не блокировать интерфейс во время генерации;
- не удалять файлы, которые созданы не AutoFill;
- не терять данные при поиске/фильтрации списков;
- корректно обрабатывать конфликты имён и отмену;
- сохранять настройки между запусками.

## 2. Стек

| Компонент | Версия | Назначение |
|---|---|---|
| Python | 3.12+ | среда выполнения |
| PySide6 | 6.11.2 | GUI, QThread, Qt resources |
| Pillow | 12.3.0 | рендер текста, PNG/PDF |
| fontTools | 4.64.0 | чтение метаданных шрифтов |
| pypdf | 5.x/6.x | сборка общего PDF |
| PyInstaller | 6.10+ | сборка одного EXE |
| Inno Setup | 6.x | установщик (опционально) |

Основная целевая платформа — Windows 10/11. Код `core` не зависит от Qt и
Pillow-совместим; Windows-специфичные вызовы (`winreg`, DWM) изолированы в
`core/windows_utils.py` и защищены проверками. CI дополнительно проверяет
сборку на Linux и macOS.

## 4. Запуск и общий поток

### 4.1. Старт приложения

1. `main.py` настраивает ротационный журнал в `%LOCALAPPDATA%\AutoFill\logs`.
2. Импортирует `resources_rc`, создаёт `QApplication`.
3. Загружает `style.qss`, иконку `:/icons/app_icon.ico`.
4. Создаёт `DiplomaGenerator`:
   - читает настройки из `SettingsStore`;
   - сканирует системные шрифты и кеш;
   - строит вкладки и панель предпросмотра;
   - применяет тему и восстанавливает геометрию/сплиттеры;
   - запускает отложенный живой предпросмотр.

Скан шрифтов выполняется при создании окна; на типичной Windows-машине он
занимает доли секунды. Кеш уменьшает повторное чтение при следующих запусках.

### 4.2. Генерация

```text
UI: проверки шаблона/шрифта/списка
UI: дубликаты и проблемные строки (быстрые измерения)
UI: предпросмотр (если включён)
UI: конфликты файлов + очистка по манифесту
UI: неизменяемый GenerationJob
        │
        ▼
QThread ── GenerationWorker.run()
             └─ core.generator.generate(progress, cancel_event)
                   ├─ load_template / load_font
                   ├─ рендер каждой страницы
                   ├─ PNG/PDF/общий PDF
                   └─ GenerationResult
        │
        ▼ queued signals
UI: прогресс/ошибки/отмена, отчёт, открытие папки
```

В worker не создаются виджеты и не показываются диалоги. Все решения
(заменить/пропустить/отменить) принимаются в UI до запуска и передаются в
`GenerationJob`.

## 5. Core

### 5.1. `core/text_render.py`

Модуль не зависит от Qt. Единая семантика координат:

- `x`/`y` — точка привязки **блока**, а не отдельной строки;
- `align` (`left`, `center`, `right`) — выравнивание строк **внутри** блока;
- `x == "center"` центрирует блок по максимальной ширине строк;
- `y == "center"` центрирует блок по сумме высот строк;
- числовой `x` при `align="center"` означает центр блока, при
  `align="right"` — правый край; при `align="left"` — левый край;
- `x_offset`/`y_offset` добавляются после вычисления привязки.

`BlockMetrics` хранит ширину, высоту, ширины строк, высоты строк, ascent и
descent. Высота строки считается как `ascent + descent`; `line_spacing`
добавляется между строками.

`text_width()` использует `font.getlength()` при нулевом трекинге (учитывается
кернинг) и сумму advance-ширин символов при ненулевом. `draw_text_block()`
рисует каждую строку с `anchor="ls"`; при трекинге — посимвольно.

`layout_block()` — единый источник геометрии для предпросмотра, проверки
границ и point picker. `check_text_bounds()` возвращает список
`(строка, переполнение_px, сторона)`, проверяет left/right/top/bottom и не
создаёт временных изображений.

### 5.2. `core/name_format.py`

- `single_line` — одна строка;
- `split_surname` — фамилия отдельно, остальное отдельно;
- `split_all` — каждое слово отдельно;
- `custom` — перенос после N-го слова;
- `auto` — жадный word-wrap на любое число строк с учётом реальной ширины и
  `margin`.

`format_name_lines()` возвращает `None` только для `auto`; решение о переносе
принимает `resolve_auto_lines()`.

### 5.3. `core/paths.py`

Безопасность и файловые операции:

- `safe_filename()` удаляет запрещённые Windows-символы и управляющие символы,
  обрезает пробелы/точки, экранирует зарезервированные имена (`CON`, `NUL`…),
  ограничивает длину;
- `safe_pdf_stem()` не допускает `имя.pdf.pdf`;
- `PathAllocator` выдаёт уникальные имена без учёта регистра; `reserve()`
  резервирует имя в текущем запуске, `resolve()` подбирает номер суффикса;
- `ensure_output_dir()` разрешает путь, создаёт папку и проверяет запись;
- `read_text_file()` читает UTF-8/UTF-16/CP1251. UTF-16 определяется **только по
  BOM**, иначе произвольный чётный CP1251-файл можно ошибочно принять за
  UTF-16;
- запись JSON/текста идёт через временный файл и `os.replace`;
- манифест `.autofill-manifest.json` хранит только относительные имена файлов,
  созданных AutoFill. `cleanup_manifest()` удаляет только их и оставляет в
  манифесте записи, которые не удалось удалить.

### 5.4. `core/generator.py`

Основные структуры:

- `RenderConfig` — шрифт, размер, цвет, позиция, интервалы, margin, режим имени;
- `OutputConfig` — папка, PNG/PDF, multi/single PDF, имя PDF, конфликтная
  политика, очистка;
- `GenerationJob` — шаблон, кортеж ФИО, render/output;
- `GenerationResult` — `created`, `skipped`, `errors`, `cancelled`, `files`,
  `total`.

Загрузка шаблона:

- `ImageOps.exif_transpose`;
- приведение к RGB/RGBA;
- DPI из `template.info["dpi"]`, иначе 150;
- шрифт загружается один раз на задание.

Сохранение:

- PNG с DPI шаблона;
- PDF через Pillow; RGBA предварительно раскладывается на белый фон;
- общий PDF: страницы сохраняются во временную папку, затем объединяются
  `pypdf`; при отсутствии `pypdf` используется `Pillow` с `append_images`;
- временные файлы удаляются в `finally`;
- метаданные PDF: title, author/creator AutoFill;
- запись атомарная: временный файл → `os.replace`.

Конфликты:

- `replace` — заменить существующий;
- `number` — подобрать `_2`, `_3`…;
- `skip` — пропустить существующий;
- `cancel` — остановиться до записи.

Повторы одинаковых ФИО внутри одного запуска нумеруются даже при политике
`replace`/`skip`, чтобы не перезаписать только что созданный файл.

Отмена (`threading.Event`) проверяется перед каждым человеком и каждой
страницей общего PDF. Уже созданные файлы не удаляются; `cancelled=True`.

Манифест обновляется объединением старых и новых файлов. Поэтому очистка
предыдущих файлов не затрагивает чужие данные.

### 5.5. `core/settings.py`

`AppSettings` — dataclass со всеми пользовательскими параметрами: пути, шрифт,
цвет текста, цвета `safe_area_color` и `marker_color`, координаты, offsets,
автоцентрирование, интервалы, margin, имя/формат, PDF, предпросмотр, тема,
геометрия, размеры сплиттеров и флаги.

`normalize_settings()`:

- игнорирует неизвестные ключи;
- приводит числа к диапазонам;
- проверяет строковые enum-поля (включая защиту от неhashable типов);
- разбирает bool-строки;
- проверяет цвета;
- фильтрует размеры сплиттеров.

`SettingsStore.save()` пишет `settings.json` атомарно и сохраняет предыдущую
версию в `.bak`. Повреждённый JSON переименовывается в
`settings.json.corrupt-<время>` и заменяется значениями по умолчанию.
После принятия редактора `main_window._apply_editor_values()` вызывает
`save_settings(silent=True)`, поэтому цвета линии полей и маркера попадают в
`settings.json` сразу, не дожидаясь выхода из приложения.

Путь по умолчанию: `%LOCALAPPDATA%\AutoFill\settings.json` (или
`APPDATA`/`~/.autofill`, если LOCALAPPDATA недоступен). Старый
`settings.json` в корне репозитория не используется и не изменяется.

### 5.6. `core/font_utils.py`

- сканирует `%WINDIR%\Fonts`, `%LOCALAPPDATA%\Microsoft\Windows\Fonts` и
  пользовательский каталог шрифтов;
- читает family/style через `fontTools.name`;
- поддерживает TTF/OTF/TTC; для TTC используется первый индекс;
- кеширует результат в `fonts_cache.json` с версией;
- `resolve_font_path()` выбирает конкретный файл по семейству/стилю, а также
  принимает прямой путь.

### 5.7. Прочие core-модули

- `screen_utils.py` — размеры окна с учётом экрана, центрирование, ограничения;
- `windows_utils.py` — безопасные обёртки `winreg`/DWM, проверка платформы;
- `version.py` — единая версия `1.1.0`;
- `name_format.py` — `plural()` для правильного «грамота/грамоты/грамот».

## 6. UI

### 6.1. Главное окно

`DiplomaGenerator` — `QMainWindow` с QTabWidget и QSplitter:

1. Основные — шаблон, шрифт, параметры, список ФИО, исключения.
2. Позиция — X/Y, offsets, автоцентр, выравнивание, safe margin, point picker.
3. Формат имени — режимы и своё разбиение.
4. Вывод — папка, PNG/PDF, multi/single, имя PDF, конфликты, очистка.
5. Настройки — тема, параметры предпросмотра, сохранение, About.

Справа — `PreviewPane`: живой предпросмотр, двойной клик/кнопка открывает
`PreviewDialog` с зумом и панорамированием. Внизу — статус, прогресс,
«Отмена», «Открыть папку», «Сгенерировать N грамот».

### 6.2. Worker и QThread

`ui/worker.py`:

- `GenerationWorker(QObject)` с сигналами `progress(int, int, str)`,
  `finished(object)`, `failed(str)`;
- `threading.Event` для отмены;
- `@Slot() run()` вызывает `core.generator.generate` и ловит все исключения;
- в `failed` передаётся traceback/сообщение; UI логирует.

`main_window`:

- создаёт `QThread` и worker, переносит worker в поток;
- соединяет сигналы queued-соединениями;
- при завершении останавливает цикл событий, ждёт поток, очищает ссылки;
- при закрытии окна во время генерации предлагает отменить и подождать;
- не уничтожает работающий QThread;
- отключает вкладки/генерацию на время работы; прогресс-бар и «Отмена»
  показываются только в активной генерации.

### 6.3. Списки

`ui/name_list.py` хранит исходный текст и отфильтрованное представление
отдельно. При активном поиске:

- редактор только для чтения;
- кнопка очистки отключена;
- загрузка/изменение применяются к полному источнику, а не к видимому тексту.

Счётчик показывает количество строк. Исключения — такой же контроллер; перенос
в основной список добавляет строки, не стирая существующие. При активном
фильтре поиск сбрасывается, чтобы добавленные строки не остались скрытыми.

### 6.4. Point picker

`PointPickerDialog` использует `QGraphicsView`:

- базовая картинка и маркер;
- тонкая сплошная safe-area рамка с настраиваемым цветом;
- цвет маркера и цвет линии полей хранятся в настройках;
- предпросмотр текста в текущем шрифте/размере/цвете через
  `render_page` с временной заменой `x/y` на позицию маркера;
- правая кнопка — поставить точку, левая — панорама, колесо — зум;
- стрелки/Shift/Ctrl — точное перемещение;
- Alt + движение мыши — расстояние до маркера;
- «В центр»;
- `showEvent`/`resizeEvent` подгоняют масштаб;
- координаты клампятся в границы изображения.

После принятия точки автоцентрирование по X/Y отключается: выбранные
координаты должны применяться буквально. Если задана только одна ось, вторая
берётся из текущего значения/центра, а не сбрасывается.

### 6.5. Диалоги и тема

`MessageDialog`:

- `clicked_index`, обычный `QDialog.Accepted/Rejected`;
- `QTextBrowser#message_text` без рамки и с прозрачным фоном;
- высота подстраивается под количество строк (220–560 px);
- primary-кнопка получает ObjectName `primary_btn`, default-кнопка
  настраивается, кнопки не уже 110 px;
- Esc/крестик — отмена.

Темы: `dark`, `light`, `system`. `style.qss` содержит стили для вкладок,
диалогов, tooltip, прогресса, groupbox, statusbar, disabled/hover/focus.
Системная тема отслеживается через `QStyleHints.colorSchemeChanged`; нативный
заголовок перекрашивается после создания HWND. Основная логика темы — в
`main_window._apply_theme()`.

Верхнее меню убрано: действия продублированы кнопками на вкладках, а
`QAction` с горячими клавишами добавлены прямо в `QMainWindow`. Быстрая
справка — кнопка `?` в правом верхнем углу вкладок.

## 7. Безопасность данных

### 7.1. Выходные файлы

- имя строится из нормализованных частей ФИО;
- запрещённые символы заменяются;
- коллизии обрабатываются `PathAllocator` без учёта регистра;
- запись атомарная;
- ошибка одного файла не останавливает остальные;
- общий PDF сначала собирается во временной папке.

### 7.2. Очистка

`cleanup_previous` удаляет только имена из
`.autofill-manifest.json` внутри выбранной папки. Проверяется, что путь
остаётся внутри папки; вложенные папки и чужие файлы не трогаются. Выбранный
шаблон исключается из очистки даже при совпадении с записью манифеста, а его
имя удаляется из манифеста. Если файл занят, он остаётся в манифесте. Очистка
выполняется после всех подтверждений, поэтому отмена конфликта/предпросмотра
не удаляет старые результаты. Генератор также не может перезаписать шаблон:
совпавшее имя автоматически получает номер.

### 7.3. Пользовательские данные

- настройки и журналы — в профиле пользователя, не в репозитории;
- `temp/` и корневой `settings.json` не коммитятся;
- настройки не удаляются, а поврежённые файлы переименовываются;
- список ФИО не сохраняется автоматически, чтобы не создавать неожиданных
  копий персональных данных.

## 8. Сборка и CI

### 8.1. Локальная сборка

```powershell
python -m pip install -r requirements.txt
python build.py
```

`build.py`:

1. находит `pyside6-rcc`;
2. всегда перекомпилирует `resources.qrc` → `resources_rc.py`;
3. проверяет иконку и `style.qss`;
4. удаляет старые `build/` и `dist/`;
5. запускает PyInstaller:

```text
--onefile --windowed --name AutoFill
--icon icons/app_icon.ico
--add-data style.qss;.
--hidden-import pypdf
--collect-submodules fontTools
--clean --noconfirm
```

Результат: `dist/AutoFill.exe`. Иконка приложения встроена как в EXE, так и в
Qt-ресурсы.

### 8.2. Установщик

`setup.iss` создаёт per-user установку (без UAC), ярлыки и uninstaller.
Компиляция:

```powershell
iscc setup.iss
```

В текущем окружении Inno Setup не установлен, поэтому установщик не
компилировался; синтаксис проверен вручную. CI может добавить шаг установки
Inno Setup.

### 8.3. CI

`.github/workflows/build.yml`:

- lint + unit-тесты на Ubuntu;
- smoke-сборка PyInstaller на Windows, macOS и Linux;
- артефакт Windows `AutoFill.exe`.

Тесты и линтер запускаются до сборки. CI не заменяет локальный headless-smoke
интерфейса и ручную проверку point picker.

## 9. Проверки

```powershell
python -m compileall -q main.py core ui tests build.py
python -m unittest discover -s tests -v
ruff check .
python build.py
```

Тесты покрывают:

- center X/Y, letter spacing, выравнивание, multi-line, offsets, overflow;
- режимы ФИО и word-wrap;
- safe_filename, safe_pdf_stem, коллизии, reserved names;
- кодировки UTF-8/UTF-16/CP1251 и защиту от ложного UTF-16;
- манифест, path traversal, сохранение неудалённых файлов, защиту шаблона;
- нормализацию произвольных/повреждённых настроек;
- PNG/PDF DPI и MediaBox;
- конфликты replace/number/skip/cancel;
- дубликаты ФИО;
- отмену до и во время генерации;
- резервную сборку PDF без `pypdf`.

## 10. Ограничения и дальнейшие шаги

- TTC: только первое лицо коллекции.
- Отмена не прерывает один уже начатый тяжёлый рендер; проверка идёт между
  файлами/страницами.
- Нет прямого импорта Excel/Word; используются TXT/CSV или вставка текста.
- Нет drag&drop и контекстного меню списков (можно добавить без изменения
  модели данных).
- `font_supports_cyrillic` не блокирует выбор шрифта: отсутствие глифов видно
  в предпросмотре.
- Системная тема на не-Windows платформах зависит от сигнала Qt.
- Установщик и CI-артефакты требуют отдельной проверки на чистой машине.
- Возможные улучшения: профили шаблонов, recent files, отдельная генерация
  исключений меньшим шрифтом, code signing.
